## 2. 测试平台

MuJoCo 桌面场景；4 自由度浮动平行夹爪（xyz + yaw，PD 位置控制，重力补偿），末端增量动作，20 Hz 控制。可达性由可行性模块单独检查，替代机械臂 IK。

- **任务族**（阶段数 H 可调，1–10）：`pack` 按顺序装入托盘槽位、`sort` 按颜色入箱、`stack` 三明治逐层堆叠。
- **感知噪声**：每个 episode 固定的物体位姿偏置（3 mm）+ 逐帧抖动（1.5 mm、0.03 rad）。策略和验证器只能看到带噪状态。
- **扰动集**：滑落（抬起初期松手）、抓取前物体被挪动、已放好的物体被撞走（移到附近空位）。数据生成另有 ARSTAG 的轨迹扰动和目标扰动。
- **专家可恢复性**：在 p=0.3 的高强度扰动下，专家 72/72 成功（3 个任务族 × H∈{4,10}，共 323 次扰动）。这仅验证这些任务与采样扰动条件的可执行性，不能据此把所有策略失败都归为学习问题。

### 4.1 主实验设计（`configs/main_v1.yaml`）

- 3 个任务族 × H∈{2,4,6,8,10}；测试集每格 20 个 episode，种子与训练集不相交，所有方法共用同一测试集；分无扰动和扰动（p=0.15）两种条件。
- **配对的匹配预算**：所有闭环方法都从同一份 8 万条开环数据起步（与开环数据池的前 8 万条完全一致），每轮追加 4 万条，共 3 轮，到 20 万条。开环在同一个 32 万条数据池的嵌套子集上评测（8/12/16/20/32 万）。因此每个预算点上的比较都是“同一份底子 + 名义数据”对比“同一份底子 + 定向数据”。
- 策略结构、训练步数、超参数在各方法之间完全一致。

### 4.2 主结果（3 个种子合并，20 万条匹配预算）

每个方法每种条件 900 个测试 episode（3 个种子 × 300）。Δ 为相对开环的成功率差（百分点），95% CI 用两比例正态近似；α 为 S(H)=S0·exp(−αH) 的二项 MLE 拟合，区间为参数 bootstrap。

| 方法 | 无扰动 | Δ [95% CI] | 扰动 p=0.15 | Δ [95% CI] | α（无扰动 / 扰动） | H≥8 成功率（无扰动 / 扰动） |
|---|---|---|---|---|---|---|
| 开环（ARSTAG 配方） | 77.6% | — | 70.1% | — | 0.044 / 0.059 | 67.2% / 58.9% |
| ours：子目标归因 RSI | 79.7% | +2.1 [−1.7, +5.9] | 72.9% | +2.8 [−1.4, +6.9] | 0.030 / 0.047 | 71.7% / 60.6% |
| oracle 归因 | 81.6% | +4.0 [+0.3, +7.7] | 73.8% | +3.7 [−0.5, +7.8] | 0.034 / 0.052 | 71.4% / 60.8% |
| 均匀再生成（闭环，无归因） | 81.7% | +4.1 [+0.4, +7.8] | 75.3% | +5.2 [+1.1, +9.3] | 0.035 / 0.049 | 69.2% / 61.4% |
| **DAgger（β 混合采集）** | **82.4%** | **+4.9 [+1.2, +8.6]** | **77.3%** | **+7.2 [+3.2, +11.3]** | **0.013 / 0.026** | **80.0% / 71.1%** |
| DAgger，归因引导（60% 的采集从被归因的子目标起步） | 79.2% | +1.7 [−2.1, +5.5] | 73.9% | +3.8 [−0.4, +7.9] | 0.034 / 0.041 | 72.5% / 65.8% |
| 混合分配（一半按归因、一半均匀） | 83.0% | +5.4 [+1.8, +9.1] | 76.1% | +6.0 [+1.9, +10.1] | 0.028 / 0.043 | 76.4% / 66.4% |
| EmbodiRSI 式（1 个种子） | 77.3% | −0.2 | 68.3% | −1.8 | 0.044 / 0.066 | 70.0% / 57.5% |
| 开环，去掉恢复演示（H3 消融） | 75.8% | −1.8 [−5.7, +2.1] | 61.4% | −8.7 [−13.0, −4.3] | 0.047 / 0.087 | 65.6% / 44.2% |
| 开环 32 万（1.6 倍数据） | 82.8% | | 77.2% | | | |

无任务图的扁平策略（顺序感知注意力，3 个种子）：开环 80.6% / 71.2%；闭环再生成对它没有显著帮助（相对扁平开环，ours −1.3 / +0.2，均匀再生成 +1.1 / +2.4，CI 均含 0）；在 H≥8 上低于分层策略（开环 63.6% / 51.7%，对比分层的 67.2% / 58.9%）。

**结论（如实）**：

1. **H1 成立**：开环成功率随阶段数指数衰减，两种条件下 α 都明显大于 0。
2. **闭环学习确实“打破了长程衰减”，但起作用的是标准 DAgger**：β 混合采集、在策略自己的状态分布上逐状态做专家标注。它的 α 只有开环的约三分之一，在 H≥8 上比开环高 12–13 个点。它的 α 区间与开环和大部分闭环方法都不重叠，只和混合分配（4.4）有一小段重叠（0.019–0.024）。在仿真里，状态专家可以零成本标注任意状态，这正是 real2sim 管线能提供、而真机 DAgger 很难负担的东西。
3. **“按子目标归因分配再生成片段”没有显著优于开环，也没有超过均匀再生成和 DAgger。** ours 在 H≥8 上优于均匀再生成（71.7% 对 69.2%，不显著），但在短任务上有损失。oracle 归因同样只和均匀再生成持平，所以瓶颈不在归因精度，而在“专家从快照续跑的片段”这种数据形式：它覆盖的是专家的状态分布，而不是策略的。
4. **任务图（分层策略）的价值体现在长程上**：扁平策略在短任务和低预算时更好，但在 H≥8 上明显不如分层策略；闭环再生成也只对分层策略有效。
5. **单个种子会误导**：种子 0 上 ours 领先开环 11 个点，主要是因为开环在那个种子的 20 万条处偶然回落（三个种子分别是 73.7%、76.3%、82.7%）。
6. **归因该用在哪里**：把归因从“分配数据”转为“把失败分流到不同的修复手段”。数据类失败交给 DAgger；重建误差、判定器偏差、任务图错误这些 DAgger 修不了的失败，交给场景修复、判定器重校准、重编译。这一点在 4.6 的 sim-real 代理上做了检验。把归因用来引导 DAgger 的起点（4.4）没有帮助。

### 4.3 H3：恢复演示主要帮助扰动后的恢复和阶段交接（3 个种子）

同一开环配方，只把恢复演示的比例设为 0（`open_loop_norec`），与完整配方在同一组预算上配对比较（Δ = 有恢复演示 − 没有，百分点）：

| 预算 | 无扰动 Δ [95% CI] | 扰动 p=0.15 Δ [95% CI] |
|---|---|---|
| 8 万 | +3.0 [−1.6, +7.6] | +5.1 [+0.6, +9.7] |
| 12 万 | +6.9 [+2.4, +11.4] | +10.4 [+5.8, +15.0] |
| 16 万 | +6.9 [+2.7, +11.0] | +13.3 [+8.9, +17.8] |
| 20 万 | +1.8 [−2.1, +5.7] | +8.7 [+4.3, +13.0] |

- 扰动条件下 4 个预算点全部显著；无扰动下只在中等预算显著，20 万条时消失。
- 去掉恢复演示后，扰动条件下的衰减率从 0.059 升到 0.087，无扰动几乎不变（0.044 对 0.047）。
- 20 万条时（900 个 episode，oracle 标签，无扰动 / 扰动），有恢复演示时：交接失败 37 / 44（没有时 59 / 53），掉落 8 / 19（29 / 35），抓取 4 / 5（13 / 21）。
- 无扰动下放置失败反而多一些（126 对 89）。

结论：H3 成立。恢复数据主要提升扰动后的恢复和阶段交接；对名义执行的收益小，数据充足时消失。

### 4.4 归因引导的 DAgger 与混合分配（3 个种子）

- **归因引导的 DAgger**（`dagger_attr`）：60% 的采集 episode 从被自动归因的失败子目标的开头快照启动，其余同标准 DAgger。
  - 20 万条时比标准 DAgger 低 3.2 / 3.4 个点（[−6.9, +0.4] / [−7.4, +0.5]）。
  - 衰减率回到 0.034 / 0.041（标准 DAgger 为 0.013 / 0.026），H≥8 成功率 72.5% / 65.8%（标准 DAgger 为 80.0% / 71.1%）。
  - DAgger 的优势来自覆盖策略自己的状态分布；把起点集中到失败处，反而缩小了这个分布。
- **混合分配**（`hybrid`，v3 报告第 7 节第 3 条）：每轮预算一半按归因分配，一半均匀分配。20 万条时 83.0% / 76.1%（无扰动 / 扰动）。
  - 相对开环 +5.4 [+1.8, +9.1] / +6.0 [+1.9, +10.1]，显著。
  - 相对只按归因（ours）+3.3 [−0.3, +6.9] / +3.2 [−0.8, +7.2]，相对均匀再生成 +1.3 / +0.8，都不显著。
  - 它是“从快照再生成片段”这一类方法里最好的：无扰动总成功率与标准 DAgger 持平（82.4%），失败总数 153/900（ours 183，均匀 165，DAgger 158）。
  - 长程仍不如 DAgger：衰减率 0.028 / 0.043（DAgger 0.013 / 0.026），H≥8 成功率 76.4% / 66.4%（DAgger 80.0% / 71.1%）。
  - v3 预测的互补只体现在放置失败上：80 次，少于 ours 的 94 和均匀的 92；交接失败 50 次，没有比 ours（47）少。

### 4.6 sim-real 代理：把失败分流到修复手段（v3 报告第 7 节第 1 条）

**测试平台**（`rsi/simreal.py`、`real2sim/recon_error.py`、`taskgraph/grounding.py`）

机器人只在自己的仿真里训练，这个仿真就是它对世界的信念。“真机”是同一模拟器里的另一套配置，与信念的差别是注入的，三类误差都是 DAgger 修不了的：
- **场景**：托盘和砧板高 2 cm，单视角重建低估为 0.6 cm。支撑面高度是 ARSTAG 表 III 里重建误差最大的一项。
- **判定器**：成功判定器的容差（tol_scale）有偏。
- **任务图**：编译器把绿色和蓝色的箱子对调。

**每轮流程**
1. 在真机上跑 60 个 episode。
2. 其中 40 个按相同任务种子在孪生体里重跑（孪生测试）。
3. 25%（15 个）人工抽检。抽检员给出任务结果，并在关键帧上标注机器人自己计划中每个子目标是否完成。
4. 最多执行一次修复。
5. 在当前的仿真里做一轮 DAgger（4 万条）。

训练数据量（8 万 + 3×4 万）、真机 episode 数和抽检数在各方法之间相同。

**归因**
- **场景**：某个任务族的“判定进度”（判定器确认的计划子目标比例）在孪生体里比真机高 0.2 以上，判为场景问题。场景问题先解释，因为错误的几何也会让判定器出错。
- **任务图**：在其余任务族的抽检失败中，机器人完成了计划里的某个子目标，但指令要求的没有完成。
- **判定器**：同样在其余任务族的抽检失败中，判定器在机器人自己的计划上与抽检员不一致。

**修复**
- **几何**：用真机日志估计支撑面高度。信号有两个：静止物体的底面，以及持物下压受阻时物体底面的高度；下方有其他物体的受阻点会被排除。
- **判定器重校准**：在关键帧标注上计算平衡准确率。当前容差已在最优区间内就不动，否则取最优区间的几何中点。
- **重编译**：按抽检员的纠正修正颜色与箱子的对应。
- **诱饵**：动力学辨识，这里没有可修的东西。

**变体**
- ours（归因路由修复）：每轮选估计份额最大的一个修复。
- ours 的不限次数版本（按证据修复）：每轮执行所有证据足够的修复。

**对照**
- 只在仿真里做 DAgger，不用真机反馈。
- 随机选修复（含诱饵）。
- 每轮所有修复都做，不限修复次数。
- 完美孪生：一开始就是真实几何、校准的判定器和正确的计划，作为上界。

#### 单一误差（`configs/simreal.yaml`，v3b 代码快照，3 个种子；`results/simreal/RESULTS.md`）

只有支撑面高度是错的，判定器宽松（×2.5）。

| 方法 | 真机成功率（无扰动）[95% CI] | 真机（扰动） | 机器人自己的仿真 | 各种子 |
|---|---|---|---|---|
| 只在仿真里 DAgger | 36.4% [33.4, 39.6] | 36.0% | 79.9% | 37 / 35 / 37 |
| **ours：归因路由修复** | **80.4% [77.7, 82.9]** | **77.4%** | 81.0% | 74 / 84 / 84 |
| 完美孪生（上界） | 80.1% [77.4, 82.6] | 78.1% | 80.1% | 82 / 84 / 74 |
| 每轮所有修复 | 71.8% [68.7, 74.6] | 70.3% | 73.4% | 76 / 59 / 80 |
| 随机修复（含诱饵） | 64.0% [60.8, 67.1] | 59.9% | 77.8% | 79 / 34 / 79 |

- **路由**：3 个种子都在第 1 轮选中几何修复，估计的支撑面高度在 19.5–20.4 mm（真值 20 mm）。之后不再修复（种子 1 第 3 轮多做了一次无害的判定器重校准），真机成功率追平完美孪生。
- **随机修复**：种子 1 三轮都没抽到几何修复，结果和不用真机反馈一样（34%）。
- **每轮所有修复**：种子 1 上坏了事。模型已经正确后再估计几何，把“往别的物体上放东西时的下压受阻”当成了支撑面，托盘高度被估成 8.8 cm，pack 掉到 0。第一次修复是排除下方有其他物体的受阻点：在已正确的模型上重估得到 19.8 / 19.1 mm，不再改动模型，三误差实验用的是这个版本。但三误差实验里又出现了另一类虚假受阻（见下），所以估计器仍不完全稳健。
- **判定器这一路一直没有证据，因为宽松判定器在这个平台上本来就无害。** 用 main_v1 的 DAgger 策略诊断（`scripts/diag/judge_scale.py`，每个容差 120 个 episode）：
  - 容差 ×1.0、×1.5、×2.5 的成功率完全相同（100/120）。
  - ×0.8 为 99，×0.6 为 95，×0.4 为 76。
  - 有害的是过严的判定器：它让 System 2 反复重做已经完成的子目标。

  所以单一误差实验实际只检验了场景修复这一路，三误差实验改用过严的判定器。

#### 三种误差（`configs/simreal3.yaml`，v3d 代码快照，3 个种子；`results/simreal3/RESULTS.md`）

误差为支撑面高度、过严判定器（×0.4）和绿 / 蓝箱子对调。

| 方法 | 真机成功率（无扰动）[95% CI] | 真机（扰动） | 机器人自己的仿真 | 各种子 | 修复次数（命中） |
|---|---|---|---|---|---|
| 只在仿真里 DAgger | 0.0% [0.0, 0.4] | 0.0% | 49.0% | 0 / 0 / 0 | — |
| **ours：归因路由修复（每轮 1 次）** | **65.2% [62.1, 68.3]** | 62.3% | 65.9% | 64 / 62 / 69 | 9（9） |
| **ours：按证据修复（不限次数）** | **70.0% [66.9, 72.9]** | 69.6% | 71.3% | 70 / 70 / 70 | 9（9） |
| 完美孪生（上界） | 79.1% [76.3, 81.6] | 77.0% | 79.1% | 77 / 79 / 82 | — |
| 每轮所有修复 | 68.6% [65.4, 71.5] | 65.2% | 69.2% | 77 / 76 / 52 | 27（13） |
| 随机修复（含诱饵） | 30.9% [28.0, 34.0] | 29.0% | 45.0% | 19 / 29 / 44 | 9（4） |

“命中”指修复时对应的误差确实还在。这是特权信息，只用于报告。

- **只在仿真里做 DAgger 完全失败**：真机 0%，它自己的仿真里却有 49%。三种误差每一种单独就能让某些任务族归零：对调的箱子让 sort 归零，错误的支撑面高度让 pack 和 stack 归零。
- **路由在 3 个种子上都用 3 轮修好了全部三种误差，每次都修对**，顺序也一样：
  - 第 1 轮修任务图：这一轮孪生测试只标出一个任务族，场景的份额较小；
  - 第 2 轮修几何：估计的支撑面高度在 19.5–20.8 mm（真值 20 mm）；
  - 第 3 轮重校准判定器：容差从 0.4 调到 1.4–1.6。

  代价是修得晚。判定器到第 3 轮才修好，大部分 DAgger 数据是在过严的判定器下采的，所以比上界低 14 个点。
- **随机修复只有 31%**：9 次修复里只有 4 次命中，3 个种子都没有修到判定器。
- **不限修复次数时，“按证据修复”与“每轮全修”的均值接近（70.0% 对 68.6%）。** 前者只用了三分之一的修复，也更稳（各种子 70 / 70 / 70，对比 77 / 76 / 52）。
  - “每轮全修”在种子 2 上又一次把已经正确的几何改坏：托盘先被估成 8.2 cm，再到 10.7 cm，pack 掉到 0。
  - 原因是过严的判定器让机器人反复重做已完成的子目标，产生了一类新的虚假“下压受阻”观测；之前加的过滤只排除了其中一部分。
  - 两组实验合计，路由和按证据修复两个变体（共 9 次运行）从没有在正确的模型上做过几何修复；“每轮全修”的 6 次运行里有 2 次把正确的模型改坏。
- **一处证据混淆**：按证据修复的种子 2 第 1 轮里，pack 还没有被孪生测试标出，它的抽检被算作判定器证据，重校准因此选了偏宽松的 2.0。宽松判定器在这里无害，但这说明“场景先解释”依赖孪生测试先检出场景问题。

**结论**：归因的作用是决定“修什么”和“要不要修”。
- 有修复预算时，它几乎总是选对（命中 9/9，随机为 4/9），真机成功率是随机选择的两倍。
- 没有预算时，它与“全修”效果相当，修复次数少三分之二，并且避开了“全修”在正确模型上改坏的风险。
- 离上界的差距主要来自修得晚：误差越早修好，DAgger 采到的数据越干净。

### 4.7 H4：仿真评估能否代替真机评估

两种检验。单一误差实验没有保存策略，只做了第一种。

**1. 单元格级**（`make_simreal_report.py`）：每个系统在它自己的仿真里和在真机上的成功率，取 15 个（任务族, H）格子算 Spearman ρ。按最终孪生体是否已校准（不再有注入误差）分组：

| 实验 | 孪生体已校准的运行：合并 ρ，仿真 − 真机 | 未校准的运行：合并 ρ，仿真 − 真机 |
|---|---|---|
| 单一误差 | 0.96，+0.002（10 次运行） | 0.60，+0.353（5 次） |
| 三种误差 | 0.98，+0.006（11 次） | 0.31，+0.272（7 次） |

只在仿真里做 DAgger 的系统，自己的仿真里是 49%，真机是 0%。

**2. 系统级排序**（`scripts/h4_rank.py`）：把三误差实验的 18 个最终系统（策略 + 它自己的信念）放进同一个孪生体里评测。只替换物理，机器人保留自己的信念；再与真机成功率比较。

| 孪生体 | 系统间 Spearman ρ | （系统, 格子）对的 ρ | 孪生 − 真机 |
|---|---|---|---|
| 未校准（机器人最初的重建） | 0.54 | 0.68 | −0.039 |
| 校准后（路由修复在种子 0 上从真机数据估出的重建） | 1.00 | 0.99 | +0.003 |

未校准的孪生体排错了两类系统：
- **低估上界系统**（信念正确、判定器容差 1.0）：孪生里 0.29–0.32，真机 0.77–0.82，被排到最差的一档。支撑面比它相信的低 1.4 cm 时，它的判定器拒绝确认放置；容差被重校准到 1.4–1.6 的系统则能接受这个偏差。
- **高估只在仿真里训练的系统**：孪生里 0.22–0.27，真机 0。

**H4 在代理上成立**：校准后的孪生体 ρ = 1.00（> 0.7），未校准的为 0.54。

**这个数字偏乐观**：代理里的“真机”与孪生体只差注入的几何，校准把它估到 1 mm 以内，没有其他未建模的差异，真机上 ρ 只会更低。它说明的是方向：没有校准的孪生体会把系统排错，用真机证据校准过的孪生体可以给系统正确排序。

### 4.8 H5：新任务的数据成本是否随已学任务数下降

`scripts/run_transfer.py`，2 个种子（合并）；`results/transfer/RESULTS.md`。

**设计**：对每个新任务族 F，先学会的任务族各提供 6 万条数据，F 自己提供 b 条，一起训练一个多任务分层策略，在 F 的留出测试集（每个种子 100 个 episode）上评测。C_task 是 F 的成功率达到 50% 所需的 F 自身数据量，预算点之间按对数线性插值。

| 已学任务族数 | b=5k | b=10k | b=20k | b=40k | C_task（均值） |
|---|---|---|---|---|---|
| 0 | 0% | 0% | 8% | 35% | 4 万条以内都达不到（0/3） |
| 1 | 9% | 21% | 41% | 61% | 25.3k（6/6 达到） |
| 2 | 21% | 39% | 59% | 73% | 14.4k（3/3 达到） |

- **三个任务族、两个种子趋势一致**：已学 0 个时，4 万条以内都到不了 50%；已学 2 个时，C_task 为 pack 21.5k、sort 9.8k、stack 11.9k。
- **没有零样本迁移**：b=0 时成功率都是 0。新任务族的目标类型（槽位、箱子、堆叠）要靠它自己的数据学会，迁移过来的是共享的抓取—搬运—放置。
- **H5 成立**：新任务的数据成本随已学任务数明显下降（4 万条以上 → 25k → 14k）。
- **局限**：只有 3 个任务族、一个技能，所以这只是“同一技能、不同目标类型”之间的复用；2 个种子，每格 200 个 episode。

### 4.9 过程中的负面结果与修正（如实记录）

- **v0（`results/main_v0`）**：闭环从 50% 的预算起步、每轮 2.7 万条时，ours 不如开环（无扰动 72.2% 对 77.1%）。诊断：定向的短片段替代了完整的名义 demo，各阶段交接状态的覆盖不足，transition 失败从 24 次升到 37 次。v1 改成先用名义数据打底、闭环小步多轮、名义混入比例 0.25，并给 System 2 加了去抖。
- **DAgger 的两个实现问题**：最初的朴素版本（β=0，重标注评测 rollout 里的全部访问状态）一路崩溃（49%→24%→14%→7%，已归档于 `results/main_v1/archive_dagger_unfiltered`）。原因一是纳入了物体掉落桌面之后的不可恢复状态；修复后（`dagger`）仍然只有约 34%，原因二是失败 episode 里卡住的那段占据了样本的大头（约一半是 approach 阶段），严重扭曲了训练分布。按 Ross et al. 2011 改为 β 混合采集（β=0.5^轮次）、每个 episode 最多 300 个样本之后（`dagger_beta`），它成了最强的方法。这条教训值得写进论文：朴素 DAgger 很容易被做成稻草人。
- **专家可恢复性**：最初的专家在扰动下会卡死，原因有全开手指压到邻近物体、高处滑落把罐子摔倒等。修正为碰撞感知的抓取朝向、夹爪预张开、低位滑落、矮罐子，之后专家达到 72/72。
- **标签一致性**：专家的对准容差原先小于感知噪声，导致标签自相矛盾，策略学成悬停。修正为容差大于噪声。
- **sim-real 代理的四处修正**（都在三误差实验之前完成，参数来自诊断脚本，没有用测试集调）：
  - **判定器误差的方向**：第一版注入的是宽松判定器（×2.5），它是一个无效的误差（4.6）。三误差实验改为过严判定器（×0.4）。
  - **几何估计器**：“每轮所有修复”在已正确的模型上重估时会被叠放物体误导（4.6）。修复后排除下方有其他物体的受阻点（`scripts/diag/geometry_obs.py`、`geometry_repair_check.py`）。
  - **孪生测试的信号**：第一版比较“判定成功率”。在过严的判定器下，仿真里的成功率本身就低，差距被封顶，第 1 轮检测不到场景错误（三误差实验的第一次启动里，随机路由的第 1 轮没有标出任何任务族）。改为比较“判定进度”后，两个策略上都能在第 1 轮检出（`scripts/diag/twin_signal.py`、`simreal3_evidence.py`）。被中断的那次启动没有留下任何结果。
  - **判定器重校准的选点**：最初在并列最优的容差里选“离当前最近的”，会停在最优区间边缘，例如 0.6，仍损失约 5 个点。改为“当前已最优就不动，否则取区间的几何中点”。
- **并行实验耗尽 Windows 提交内存**：每个 worker 的 OpenBLAS 按核数预留缓冲（约 830 MB），多个实验同时跑时作业开始报错。worker 改为单线程 BLAS 后降到约 40 MB（`datagen/parallel.py`）。出错的那两次启动（混合分配、H5）已作废重跑。

## 5. 范围与局限（如实说明）

**这一轮处理了的**（对照上一版的本节）：

- **RSI 动作空间不再只有数据算子。** 场景修复（支撑面高度）、判定器重校准、任务图重编译都接进了闭环，由孪生测试和人工抽检做归因、每轮选一个修复（4.6）。
  - 重编译目前只覆盖一类可注入的编译错误（颜色与箱子的对应），由抽检员的纠正直接修正，还不是让 LLM 编译器带着反馈重新生成。
- **H4 在代理上做了检验**（4.7）：“真机”由同一模拟器里的另一套配置代替。
- **H3、H5 做了检验**（4.3、4.8）；v3 报告第 7 节列出的三个后续实验（sim-real 代理、归因引导的 DAgger、混合分配）都已完成（4.4、4.6）。

**仍然存在的**：

- **没有真机，也没有图像输入的 VLA。**
  - sim-real 代理的误差类型是注入的，修复算子也是针对这些类型设计的。真实世界里会有没有对应修复算子的误差，路由只能在已有的修复里挑。
  - System 1 仍是低维状态 BC。这台机器是 Windows + 8 GB 显存，而 openpi 的 π0.5 微调需要 Linux 和 24 GB 以上显存。LeRobot 的 ACT / DP 可以在这里训练，但需要先搭渲染图像的数据管线，这是下一步（见 `BASELINES.md`）。
- **抽检员是用特权状态模拟的**，标签没有噪声；真实抽检会出错，判定器重校准在噪声标签下的表现没有测。孪生测试也假设能在孪生体里按相同任务种子重放真机 episode。
- **real2sim 前端仍是接口级实现。** Claude 只生成粗略的 SceneSpec，几何精确的重建要接 Agentic RSR / Real2Gym（导入器已测试）。实验里没有调用 Claude：它需要 API 凭据，也会产生费用。
- **技能库只有 `pick_place`**：没有推、开合、插入、倾倒等技能，也没有非抓取翻正。H5 的迁移因此只是“同一技能、不同目标类型”之间的迁移。
- **浮动夹爪**代替机械臂，可达性由虚拟机械臂模型近似。
- **统计功效**：主要比较都是 3 个种子。随机路由这类方差很大的对照（单一误差实验里三个种子分别是 79%、34%、79%），3 个种子只能说明“会出现很差的情况”，不足以给出精确的均值。


## 6. 2026-10-25：累计修复成本、观测重放与 Physical2RSI

新增实现：`src/horizon/rsi/repair_cascade.py`，接入
`src/horizon/rsi/simreal.py`。

- `cost_gated`：对几何、判定器和任务图三个候选修复做精确子集选择，在剩余累计成本内最大化证据份额。
- `cascade`：每个 episode 一票的几何稳健估计 → 用原始观测和修正后的 belief 重算审计判定 → 按完整 episode 分开的拟合/检查 → 任务图纠正。检查集需要支持候选更新，且校准前两组都必须有独立误读证据，避免为无信息的拟合消耗预算。真正执行但被拒绝的拟合仍计费。
- `cascade_no_replay` 消融：相同顺序和预算，关闭修复后对既有观测的重放。
- `repair_budget` 是跨轮次累计预算，`repair_costs` 可配置非均匀算子成本。目前使用抽象单位，不等于人工分钟或机器人试验时间；部署次数和审计次数单独统计。
- `paired_feedback: true` 将每轮反馈/采样随机数与修复动作解耦，孪生重放使用相同 rollout 随机种子。旧配置默认保持原协议，因此旧结果与新协议需要分开报告。
- 自定义测试分布现在按配置生效；零审计预算不会隐式变成一次审计；部署或孪生 rollout 出错会明确报错。

Physical2RSI 是综述/资源索引，已固定官方仓库提交并补入
[baseline 文档](../baselines/Physical2RSI.md)；它本身不是可直接运行的算法。
当前修复规则是固定的，不能据此声称改进了 improver 本身。

3 轮反馈、每轮 60 次部署 / 15 个审计 episode、累计 3 成本单位。该配置已准备，
