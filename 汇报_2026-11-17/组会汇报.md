# 组会汇报：部署失败诊断驱动的学习操作选择

2026-11-17｜本目录是全部实验产物的汇总

---

## 0. 一页结论

**主张**：部署失败的原因不同，该做的学习操作就不同；从部署反馈诊断原因再选操作，在相同预算下优于任何固定配方。

| 证据 | 数字（配对 bootstrap 95% CI） |
|---|---|
| 没有单一操作通吃两类原因 | 几何：校准 **+38.3 pp [+35.0, +40.0]**；覆盖：定向再生成 **+51.7 pp [+40.0, +70.0]**；交叉为 0 或负 |
| 选择器优于固定配方 | 覆盖 **+31.3 [+27.2, +35.7]**、几何 **+7.0 [+3.2, +11.2]**（180 runs / 3 种子） |
| 原因混杂时差距最大 | 混合原因下固定配方丢 **24.0 pp [+10.0, +41.0]** |
| 原因可辨识 | 二类留一法 **100%**；三类 **88.9%**，但混合只有 **30%** |

最强的一条负结果：覆盖不足下固定配方**从未**达到参考序列 90%，规则在第 2 轮（29 次部署）跨过。

## 4. 五类失败原因（本轮新增）

| 原因 | 构造方式 | 正确操作 |
|---|---|---|
| 几何偏差 | `recon.bias` 0.46（信念 9.2 mm vs 真实 20 mm） | `calibrate_geometry` |
| 覆盖不足 | 初始数据只采 `x ≤ 0`（`layout_prior: left_half`） | `regenerate_targeted` |
| **恢复不足** | 初始数据无恢复演示 + 部署扰动 0.4 | `add_recovery_data` |
| **动力学（摩擦）** | 部署世界 `friction_scale: 0.55`（MJCF 里 μ 由 1.0 → 0.559） | `randomize_physics`（新增动作） |
| **健康** | 无偏差、满覆盖 | `stop` |

运行中：5 原因 × 3 实例 × 3 选择器 = 45 runs（协议预算 80k/40k/8000）。

### 五类可辨识性：能分辨纯原因，分不出混合

留一法多项逻辑回归，特征只用选择器能看到的量（校准残差、失败集中度、失败子目标数、失败类型占比）。

| 真实 \ 预测 | coverage | geometry | mixed | recall |
|---|---:|---:|---:|---:|
| coverage_deficit | **99** | 0 | 6 | 94% |
| geometry_bias | 0 | **108** | 0 | 100% |
| mixed_cause | 21 | 0 | **9** | **30%** |

（243 样本，总体 88.9%；动力学/恢复/健康待 45 runs 跑完后并入。）

**这是必须报的一条**：纯原因分得很开（94%/100%），但**混合原因只有 30% 被认出，70% 被误判成纯覆盖**。
所以方法上不能宣称"五类都分得开"；混合原因要么单列一类并要求额外证据，要么承认诊断在这一档失效。

# 六、补充（2026-11-18）：平台能表达哪些失败原因

导师的方案列了五类原因。逐类验证后，**这个平台只能表达四类**，结论如下。

| 原因 | 能否构造 | 证据 |
|---|---|---|
| 几何偏差 | ✅ 可分级 | 表 9：无偏差 +0.000 → 6 mm +0.650，单调 |
| 覆盖不足 | ✅ 可分级 | 初始数据只采半区，基线 0.05–0.10 |
| 恢复不足 | ✅ 可分级（需扰动模式） | eval_pert 0.7 时基线从 0.90 降到 **0.35** |
| 健康 | ✅ | 基线约 0.90 |
| **动力学（摩擦/质量）** | ❌ **不可表达** | 见下 |

## 动力学为什么测不出来

| 旋钮 | 扫描 | 结果 |
|---|---|---|
| 摩擦系数 | 1.0 → 0.2 | SR 恒为 **0.750 / 0.700**，完全无变化 |
| 质量 | 1× → 8× | 0.750 / 0.750 / 0.800 / 0.700 / 0.750，噪声内 |
| 控制延迟 | 0 / 1 / 2 / 3 / 4 | 0.750 / 0.850 / **0.000** / 0.000 / 0.000 |

- 摩擦与质量无效：夹爪是**力闭合**夹持，竖直搬运时物体—桌面摩擦和物体自重都不起决定作用。
- 延迟有效但是**二值**：≤1 无影响，≥2 全崩，**没有"约 40%"的中间档**。

→ 所以论文里动力学应写成"该平台不支持的失败原因"，并附这三组扫描；
**不能**为了凑五类而硬塞一列（那一列会全是 0 或全无差异）。

## 另一个被修掉的口径问题

`evaluate` 的扰动原本**硬编码 0.15**，而记录只取名义 SR——所以"恢复不足"一直被掩盖
（名义 0.900 恒定，扰动才显现缺陷）。现在 `eval_pert` 与 `eval_mode` 都可按场景配置。

## 位置偏差的处理

`lateral_offset` 到 5 cm 专家仍 4/4 成功，场景可用；但 `geometry_repair` **只估高度、没有位置估计器**，
所以位置偏差只能当"未知原因"（正确做法是别乱修），不能当"校准能修"的条件。

## 选择器补齐

导师列的 8 个里，我现在有 6 个：固定 / 规则 / **随机** / **轮流** / **Bandit(UCB)** / Oracle，
LLM 与 LLM+经验待密钥。随机、轮流、bandit 是"是不是挑软柿子"的直接回答，已进当前实验。
