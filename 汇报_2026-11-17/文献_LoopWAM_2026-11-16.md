# LoopWAM 精读：它到底做不做"按原因选操作"

来源：`baselines/2610.18873v2.pdf`，*LoopWAM: Closed-Loop Generalist Policy Improvement from Deployment
Rollouts*，arXiv:2610.18873v2（2026-10-15），清华 / Dexmal / Loopeva。

> 更正：我此前说"LoopWAM 本地零资料"是错的——我当时只用 `.md` 做了 grep，漏了这个 PDF。

## 一、它做什么（原文可引）

每一轮的流程是**固定**的，原文 §4.2：

> "In each deployment round, we run each model on its assigned tasks and collect about 100 rollout
trajectories per task. These trajectories are quality-annotated and combined with expert demonstrations
and rollout trajectories from all previous deployment rounds for further training."

即：部署 → 每任务采 ~100 条 → 质量标注 → 与**全部历史数据**混合 → 重训。
**每一轮都这样，没有任何分支。**

方法侧只有一件事：source-dependent noise sampling + quality steering + quality-weighted supervision，
把所有质量的 rollout 一起用。

结果：RoboChallenge Table30-V2，三轮 23.67% → 28.00% → 37.67% → **43.33%**（score 36.10 → 56.80），
+19.7 pp。RoboTwin 2.0 平均 94.5%，RoboCasa365 49.5%；衬衫折叠两轮 13.20% → 55.56%。

## 二、导师那 5 个问题，逐条回答

| 问题 | 答案 | 证据 |
|---|---|---|
| 1 每轮固定还是按失败调整？ | **固定** | §4.2/§4.4 原文；每轮同一流程 |
| 2 若做选择，依据是什么、动作空间几个？ | **不做选择**，动作空间只有"再训练"一个 | 全文 `diagnos` 0 次、`budget` 0 次、`decide` 0 次、`curriculum` 0 次 |
| 3 算不算成本？ | 报数据量（~100 rollouts/task/轮）与轮数（3），但**没有成本—收益权衡**；`cost` 全文仅 1 次且出现在参考文献标题 | 同上 |
| 4 有没有在 twin 里先试错？ | **没有** | `twin` 16 次全部是 RoboTwin 基准；`digital twin` 0 次 |
| 5 是否只一种失败原因？ | 不是——它有**真实多样的失败**（30 任务、4 种机器人、自然失败），但**对所有失败用同一个处方** | §4.4 只报聚合指标，无分任务/回归分析 |

## 三、这条对定位意味着什么

LoopWAM 是**比 v5–v7 更有力的对照**：它的测试床恰好满足导师"agent 要有价值"的第一个条件
（失败原因多样），却不满足第二、第三条（不做诊断、不算预算）。它选了"对所有失败一视同仁"。

所以我的位置可以写成一句可辩护的话：

> LoopWAM 在真实部署闭环上证明了"收数据再训"能涨 19.7 pp，但它对每一轮都做同一件事，
> 且只报聚合；我们问的是同一批失败里**哪一类该修 twin、哪一类该补数据**，并把预算算进去。

三条具体差异，全部来自原文而非推测：

1. **无诊断**：它不做原因区分，我们对两类原因的首步判断正确率是 19/20（规则）与 20/20（oracle）。
2. **无预算**：它只报数据量，不报"多花 X 换 Y 点"；我们的表 9 给出同一策略下校准收益
   从 +0.000（无偏差）到 +0.650（6 mm）的完整曲线。
3. **无孪生**：它没有可在上真机前试错的后端；我们的候选操作先在 twin 里核验。

## 四、必须承认的一条风险

它在 3 个公开榜单上都是对比方法里最好的（RoboTwin 94.5%、RoboCasa365 49.5%、RoboChallenge 第一）。
审稿人会问："你说固定处方不好，可它拿了 SOTA。" 准备好在论文里正面回答：

- 它证明的是**聚合指标**能涨；它没有报告有没有任务在涨的同时退步，而这是"一个处方打天下"
  最可能藏问题的地方：
- 我们在自己的测试床上测到了这种异质性：几何场景下 `uniform` 再生成是 **−13.3 pp [−20.0, −10.0]**，
  而同一个操作在校准之后变成 **+46.7 pp**。同一操作换个位置，符号就反了。
- 所以主张不是"闭环重训无用"，而是"闭环重训在原因不匹配时会白花甚至变差；先诊断能把这份预算
  花在对的地方"。
